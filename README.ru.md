# Xcode Pilot

[English](README.md) · **Русский**

Приложение в строке меню macOS для сборки и запуска Xcode-проектов без открытого Xcode.
Всё делается через `xcodebuild`, `simctl` и `devicectl`, поэтому Xcode.app может быть закрыт.

## Что умеет

- **Выбор проекта**: `.xcodeproj`, `.xcworkspace` или Swift-пакет (папка с `Package.swift`).
  Недавние проекты запоминаются, проекты, которые недавно открывал Xcode, подтягиваются из DerivedData.
- **Схема, run destination и конфигурация** — как в тулбаре Xcode. Список устройств берётся из
  `xcodebuild -showdestinations`, поэтому показывает только то, на чём схема реально запускается.
- **Build / Run / Stop / Test / Clean / Archive**. Run собирает, ставит и запускает приложение
  на симуляторе (с загрузкой симулятора), на подключённом устройстве или на Mac и остаётся
  подключённым к нему: вывод `print` идёт во вкладку «Консоль».
- **Ошибки и предупреждения прямо в панели**: файл и строка, фрагмент кода от компилятора, фильтр
  ошибки/предупреждения. Любую ошибку можно скопировать (в формате `file:line:col: error: …`),
  скопировать все разом, открыть в Xcode, VS Code, Cursor или Zed на нужной строке.
  После сборки список сверяется с `.xcresult`, так что ничего не теряется и не дублируется.
- **Лог сборки** — краткий (задачи, диагностика, результат) или полный, с поиском (⌘F).
- **Архив** кладётся туда же, куда его кладёт Xcode, и сразу виден в Organizer. Из панели архив
  можно открыть в Organizer, экспортировать (App Store Connect, Ad Hoc, Development, Enterprise,
  Developer ID) или загрузить в App Store Connect.
- **Organizer и Devices and Simulators** открываются кнопками в панели и в меню иконки.
  А для повседневного есть своя вкладка «Устройства»: симуляторы (загрузить, выключить, показать)
  и подключённые девайсы, любой можно выбрать для запуска.
- **Иконка в строке меню показывает состояние**: кольцо прогресса при сборке (оценка по
  длительности прошлой такой же сборки), время сборки рядом с иконкой, зелёный бейдж при успехе,
  красный бейдж и число ошибок при неудаче, отдельные состояния для установки и запущенного приложения.
  По клику правой кнопкой — меню с основными действиями, выбором проекта, схемы и устройства.
- **Глобальные сочетания клавиш**: ⌃⌥⌘R — запустить, ⌃⌥⌘B — собрать, ⌃⌥⌘. — остановить,
  ⌃⌥⌘X — показать или скрыть панель. Внутри панели работают привычные ⌘R, ⌘B, ⌘., ⌘U, ⇧⌘K.
- Уведомление о завершении, если панель закрыта; звуки; запуск при входе; выбор версии Xcode,
  если их установлено несколько; панель можно открепить в отдельное окно.

## Сборка

Нужны Xcode 26, [XcodeGen](https://github.com/yonaskolb/XcodeGen), [SwiftGen](https://github.com/SwiftGen/SwiftGen)
и [SwiftLint](https://github.com/realm/SwiftLint) (`brew install xcodegen swiftgen swiftlint`).

```bash
cd Scripts && ./generateProject.sh
```

Затем открыть `XcodePilot.xcodeproj` и запустить схему `XcodePilot`. Команда разработчика задаётся в
`Scripts/project.env` (`DEVELOPMENT_TEAM_ID`).

## Разрешения

- **Универсальный доступ** — только для кнопок Organizer и Devices and Simulators: у Xcode нет
  URL-схемы или AppleScript-команды для этих окон, приложение нажимает их пункты в меню Window.
- **Уведомления** — спрашиваются при первом уведомлении о завершении сборки.

## Ограничения

- Пока Xcode сам собирает тот же проект, параллельная сборка из Xcode Pilot упрётся в блокировку
  DerivedData — они делят одну папку, чтобы инкрементальная сборка была общей.
- Пакеты с макросами и плагинами, которым ни разу не доверяли в Xcode, xcodebuild не соберёт;
  для них в настройках есть «Не проверять макросы и плагины».
- Запуск на Mac в варианте «Designed for iPad» не поддерживается, такие destinations скрыты.
- Прогресс сборки — оценка по времени прошлой успешной сборки той же схемы: xcodebuild не сообщает
  общее число задач.

## Архитектура

Слои View → ViewModel → Provider → Core Service, DI через локаторы, генерируемый проект и ресурсы
через SwiftGen — подробности в [CLAUDE.md](CLAUDE.md).
